All branches start at `eb/screens-layout` (eb18 `54dc816` plus the design). A track that changes Settings makes a
`denial-apps` worktree `denial-apps-<short>` on the same branch name from `denial-apps` `eb/screens-layout` (`4f8304a`).

Boundaries, to keep merges small:
- S owns search: the SDK search model, the launcher plugin's catalog and matching, the overview hub's search field and
  results, the search over the desktop, the tablet drawer and pull-down search, and the routing of bare Super, Super+S,
  Alt+F and four fingers up.
- P owns the overview's drag and drop (`desktop_screens_overview_layout.dart` and its drop zones) and split geometry in
  `deniald`.
- M owns the presentation switch in `deniald` and the shell, and the mobile Split View ↔ split screen mapping.
- R owns tablet Recents (`app_deck_layer.dart` and its parts).
- F owns frame pacing in `deniald` (frame scheduler, output scheduler, render path, CPU/GPU hints) and cross-cutting
  shell costs (backdrop blur, layers, shader warm-up). For a cost inside code another track rewrites, F reports the
  measured cause to the coordinator, who forwards it, rather than editing that code in parallel.
- Protocol (`protocol/denial.fbs`): add fields only at the end of tables. A track that changes it says so in its
  report; the coordinator regenerates the code after merges.

## Builds and tests (docs/EB-BUILD.md)

Builds are serialized with `flock`: `~/.eb19-cargo.lock` for `eb-build-deniald`/`eb-build-settings` (build and test),
`~/.eb19-flutter.lock` for `eb-build-shell` and the Dart tests (`~/work-denial-screens/run-dart-tests.sh CHECKOUT
LOGPREFIX`). Use `EB_WORK=<work dir>/deniald` for `deniald`, `EB_WORK=<work dir>/settings` for Settings, and your own
output directories. The shell's cache stays `~/work-denial-shell` (default `EB_WORK` of `eb-build-shell`).

Baseline (eb18, `54dc816`): `deniald` 888/893 (4 known qemu/WSL failures), shell 413 + 12 engine-only failures, SDK 135,
Settings 66 + 1 known failure. Every track keeps these and adds tests for its behaviour.

A test package for the tablet: `tools/eb-repack-deb SHELL_OUT 0.6.8-1+eb19~<track><n> DEBS DENIALD SETTINGS` with
`EB_PORTAL=` the portal built with that `deniald`. A track that does not change Settings passes the eb18 Settings build
`~/work-denial-eb19/settings-out/settings` (never leave the fifth argument out: that would ship the release's Settings).
`~<track><n>` versions sort between eb18 and eb19.

## The tablet

One holder at a time: `D:\androidlinux\tools\tablet-lock.sh acquire NAME [WAIT_MIN]` / `release NAME` / `status`.
Only the holder installs packages, restarts the session, changes settings or injects input. Hold it for one test
session, not for PC work. Before release, put back the owner's settings (`layout.windowLayout screens`,
`shortcuts.preset mac`, `presentation.followKeyboard true`, desktop presentation with the cover attached), close test
apps, and write what is installed into your log. The coordinator keeps `power.stayAwake true` for the whole run and
turns it off at the end; tracks do not change it.

Rules from `D:\androidlinux\AGENTS.md` apply: no partitions, no fastboot, no reboots, stop below 40 % battery, no sleep
inhibitors, back up a replaced system file next to it. Logs go to `D:\androidlinux\device-logs\eb19-<track>-*`.
`tools/tab/vinput.py` (on the tablet `/usr/local/sbin/erhai-test-input`) is shared: changes are additive, and the
tablet copy is refreshed only by the lock holder.

## Merge

Each track: commits with tests, pushed to `origin`, a report with tablet evidence. The coordinator reviews, merges into
`eb/screens-layout`, and the next tracks merge `eb/screens-layout` into their branch before their final tablet check.
The integrated build (`~/work-denial-eb19/build-all.sh 0.6.8-1+eb19`) is checked on the tablet with
`tools/tab/eb19-check.sh` and the frame measurement; only then are both forks' `eb/main` moved.
